# キリンジ シフト・作業割当アプリ

添付された「キリンジ-シフト・作業割当アプリ (29).zip」のReactソースを基に、Codexで開発できる形に再構成しています。月間シフト（21日〜翌20日・2か月表示）、個人の作業計画／実績、日別全体割当、スタッフ・略称・2週間シフトパターン・作業パターン、振休管理、印刷、CSV実績出力、単体HTMLの生成を引き継いでいます。

## Windowsでダブルクリックして起動

ZIPを解凍したフォルダにある **`アプリ起動.bat`** をダブルクリックしてください。毎回コマンドを入力する必要はありません。

- 初回はNode.jsを確認し、未導入ならWindowsのwingetでLTS版のインストールを試みます。利用できない場合は公式ダウンロードページが開くので、Node.js LTSを一度インストールしてから再実行してください。Windowsがインストールの確認を表示した場合は内容を確認してください。
- 必要な依存関係を初回に自動インストールし、ダウンロード用HTMLも自動生成します。以降は変更がなければ準備を省略します。
- サーバーが起動したことを確認してから、既定のブラウザでアプリを開きます。
- 同じフォルダのアプリが起動済みなら、その画面を開きます。別のプログラムがポート3000を使用している場合はエラーを表示します。
- 起動時の黒い画面は、使用中は開いたままにしてください。閉じるとサーバーが終了します。ブラウザだけを閉じてもサーバーは終了しません。

初回のインストールとFirebase共有保存にはインターネット接続が必要です。起動ファイルは登録済みのデータを削除しません。Windows実機でのダブルクリック／winget動作は、このLinux環境では未検証です。

### 起動できない場合

ZIPの中から直接実行せず、ZIPを右クリックして「すべて展開」したフォルダで起動してください。起動に失敗しても黒い画面は閉じず、最後のエラーを確認できます。`startup.log`にも実行日時、Node.jsのバージョン、準備処理の出力、失敗理由を記録します。フォルダに書き込めない場合はデスクトップやドキュメントへフォルダを移してください。

以前起動した黒い画面が残っている場合は一度閉じてから再実行してください。ブラウザだけ開かない場合は、起動画面の「READY」の後に表示されるURLをブラウザで開いてください。

## 起動

Node.js 22以上を使用してください。検証環境はNode.js 24です。

```sh
npm ci
npm run dev
```

開発サーバーはポート3000です。Gemini APIキーは不要です。

```sh
npm run lint       # TypeScript
npm run build      # 本番ビルドと単体HTMLの生成
npm test           # 共有DBに接続しない画面テスト
node --test tests/launcher.test.mjs  # 起動・再利用・ポート競合
node --import tsx --test tests/compensatory.test.ts  # 振休再計算
```

Playwrightはシステムの`/usr/bin/chromium`があれば使用します。それ以外は`npx playwright install chromium`でブラウザを導入してください。`CHROMIUM_PATH`で実行ファイルを指定できます。

## 振休の自動割当

シフト編集モードで振休や休日出勤を追加・変更・削除し、**「編集モード解除」** を押すと、スタッフごとに振休の日付順で充当元を再計算します。未使用の過去の休日出勤のうち最も古い日を優先し、なければ最も近い将来の休日出勤を使います。削除した振休の充当元はほかの振休で再利用できます。

編集中は既存の割当を維持し、解除時にまとめて更新します。休日出勤が足りない振休は削除せず未割当として残し、対象者・日付を表示します。田中・高畠・三浦の既存の適用開始日を維持し、シフト区分、ロック、メモなどは再計算で変更しません。登録済みシフトの送信とサーバー側のデータ取得を確認してから再計算するため、オフライン時や権限エラー時は編集モードを維持し、再試行を案内します。

## Firebase共有保存

添付ファイルの`firebase-applet-config.json`に記載されたFirebaseプロジェクトと名前付きFirestoreデータベースに接続します。複数の端末が同じ設定を使用すると、シフト・作業割当・メモ・スタッフ・設定を共有します。接続設定はFirebase Webアプリの公開メタデータで、サービスアカウントの秘密鍵ではありません。

別のプロジェクトを使用する場合は`.env.example`を参考に、`.env.local`で`VITE_FIREBASE_CONFIG`にJSON形式のWebアプリ設定を指定してください。変更後は開発サーバーを再起動し、単体HTMLも再ビルドしてください。サービスアカウントの秘密鍵をブラウザ向け変数に入れないでください。

FirestoreのIndexedDB永続キャッシュを有効にしています。取得済みデータと未送信の編集を保存し、再接続時に同期します。画面右下で「接続待ち」「変更を送信中」「同期済み」「接続エラー」を区別します。初回の取得には接続が必要です。起動時に既存シフトや過去の振休を自動で書き換える処理はありません。

元アプリの編集用パスワードは`ks1311`です。この画面上の操作制限はFirebase認証ではありません。`firestore.rules`は登録した共用UIDだけを許可するルールです。本番への適用はまだ行っていません。公開手順は末尾を参照してください。

クラウド環境の通信許可には`firestore.googleapis.com`が必要です。Firebase接続エラーや接続待ちが続く場合は通信許可、プロジェクト／データベースID、Firestoreアクセス権を確認してください。

## データを変更せず共有機能をテストする

実データのある接続先へテストデータを書き込まないでください。次のコマンドは`demo-kirinji`という隔離プロジェクトのローカルFirestoreエミュレーターを起動し、独立した2ブラウザでシフト／作業計画の同期とリロード後の保持を検証します。

```sh
npm run test:sync
```

Java 21以上が必要です。初回のエミュレーター取得には`storage.googleapis.com`へのアクセスが必要です。クラウド環境では設定・キャッシュを`/workspace/.config`と`/workspace/.cache/firebase/emulators`に保存します。テスト用サーバーのポートは3001、エミュレーターは8080です。UIテストは3002を使用します。

## 単体HTML

`npm run build`で、`dist/index.html`と`kirinji_shift_app.html`／`.htm`を生成します。`public/`と`dist/`にもダウンロード用コピーを生成し、設定画面の「パソコンに保存」から取得できます。Firebase認証を使用するため、HostingのURLまたは起動プログラムによるHTTP配信で開いてください。Firebaseとの共有には通信接続と有効なアクセス権が必要です。登録されたクラウドデータ自体はHTMLファイルには含まれません。

## 引き継ぎ方針

既存のデータ形式・コレクション名を維持しています。既存のクラウドデータを削除・移行する処理は実行していません。添付の生成済みHTMLは再利用せず、引き継いだソースから再生成します。端末内キャッシュはIndexedDBで、元資料にあったlocalStorageや自動オフライン同期についての記述を実際の実装に合わせて修正しています。

Windowsでは `サイト公開.bat` をダブルクリックすると、インストール・Googleログイン・ビルド・Hosting公開を順に実行します。公開処理にはインターネット接続が必要です。このプログラムはFirestoreルールを変更しません。

手動の場合はアプリのフォルダーで以下を実行します。Firebase のプロジェクトを管理できるGoogleアカウントでログインしてください。

```sh
npx firebase login
npm run build
npx firebase deploy --only hosting --project gen-lang-client-0437386118
```

公開URLは `https://gen-lang-client-0437386118.web.app` です。
共用アカウントでログインして既存データが表示されることを確認後、
Firebase Consoleで対象データベースのルール全文を `firestore.rules` の内容に置き換えて公開します。
CLIでのルール適用は次のコマンドです。対象は firebase.json に指定した名前付きデータベースです。

```sh
npx firebase deploy --only firestore:rules --project gen-lang-client-0437386118
```

ルールを公開すると、Firebaseログイン未対応の旧アプリは読み書きできなくなります。
各端末を公開URLに切り替えてください。ルールの公開は既存ドキュメントを削除しません。
Firebaseへのサイト公開・本番ルール適用は、プロジェクト管理者の認証が必要です。
パスワードやサービスアカウントの秘密鍵をソース・チャットに貼らないでください。

開発テストは認証／Firestoreエミュレーターだけを使います。
`VITE_DEMO_UI=1` は `demo-` プロジェクトの画面テスト専用で、本番では無効です。
